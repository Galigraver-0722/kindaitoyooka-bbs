# MVP スコープ

> 日本語版です。英語版が正本です: [English](../01-mvp-scope.md)

## 定義

MVP は **動く骨格（walking skeleton）** です。各層が薄くても、システムのすべての層がそろい、つながっています。生徒は登録し、読み、スレッドを立て、返信し、投稿を通報できます。モデレーターは投稿を削除し、スレッドをロックし、通報キューを片付けられます。

これらの操作がどれか 1 つでも欠けていれば、それは MVP ではなく試作品です。

## すでに実装済みのこと（v0.1）

- メール任意の登録、ログイン、ログアウト。セッションはサーバー側で管理。
- シード済みのボード 5 つとサンプルの議論。
- ボード一覧、最近の活動、スレッド一覧、スレッド表示。
- スレッドの作成、スレッドへの返信。
- 投稿へのいいね、スレッドの保存、共有リンク、通報を 1 つの操作バーにまとめた導線。
- 保存したスレッドの一覧ページと、利用者ごとのリアクション状態。
- タイトルと返信を対象にした検索。新着順と人気順で並べ替えられる。
- 投稿フォームと返信フォームの専用タグ欄。タグで絞り込んだ検索もできる。
- ログイン、登録、投稿、通報、リアクションに固定ウィンドウのレート制限。環境変数で調整できる。
- ボードページのページ送り（1 ページ 20 件）。新着順・人気順のどちらでも使える。
- コミュニティルール、プライバシー通知、モデレーション方針の公開ページ（英日両方）。
- モデレーション操作の監査ログ。`/moderation` で確認できる。
- `/u/<username>` のプロフィール。参加日と、最近のスレッド・投稿を表示する。
- 投稿から 15 分以内のスレッド編集と、「編集済み」の表示。
- `/t/<id>/export` からの、スレッドのプレーンテキスト書き出し。
- ログイン中の利用者向けの、ホームとボード一覧の未読バッジ。
- 投稿・返信フォームの、ボードごとのおすすめタグ。
- 保守用コマンドによる手作業のパスワード復旧と、`GET /health`。
- CC BY 4.0 の `naughty-words` リストによる自動の要注意語フラグ。判定は人間が行う。
- 理由必須の通報。
- モデレーターのキュー: 通報された投稿の削除、または通報の却下。
- モデレーターの操作: 投稿の削除、スレッドのロック／解除、スレッドの削除。
- 論理削除。黙って消すのではなく、見えるプレースホルダーを残す。
- ロール表示（英語では `student` など、日本語では「生徒」など）とサーバー側の権限チェック。
- 日本語を既定とする画面。ヘッダーから英語に切り替えられ、選択は Cookie に保存される。日付と件数もロケールに従う。
- レスポンシブなレイアウト、プレーンテキストのみ。

## MoSCoW

### Must（v0.1 の公開に必須）

| 機能 | 受け入れ条件 |
| --- | --- |
| 登録 | ユーザー名 3〜20 文字 `[a-z0-9_]`、パスワード 10 文字以上、重複したユーザー名は読めるメッセージで拒否 |
| ログイン／ログアウト | 再読み込みしてもセッションが続く。ログアウトでサーバー側のセッションが無効になる |
| 閲覧 | ゲストがアカウントなしでボード、スレッド一覧、スレッドを読める |
| スレッド作成 | ログイン済みの利用者がボードを選び、タイトル 3〜120 文字、本文 10,000 文字以内 |
| 返信 | ログイン済みの利用者が、ロックされておらず削除されていないスレッドに返信できる |
| 通報 | ログイン済みの利用者が、表示中のどの投稿でも 3〜500 文字の理由で通報できる |
| モデレーション | モデレーターが投稿の削除、スレッドのロック、スレッドの削除、通報の処理を行える |
| 権限 | 生徒は `/moderation` に到達できず、モデレーション用エンドポイントも呼べない |
| 安全のプレースホルダー | 削除された投稿は、言語に合わせた表示（「Removed by a moderator」または「モデレーターが削除しました」）でスレッドに残る |
| 言語の切り替え | どのページも既定では日本語で開き、英語にも切り替えられる。選んだ言語は画面を移っても保たれる |
| リアクション | ログイン済みの利用者が投稿にいいねし、スレッドを保存できる。件数が更新され、もう一度押すと取り消せる |
| 検索とタグ | タイトルと返信を検索でき、タグで絞り込み、新着順または人気順で並べられる |
| 不正利用対策 | ログイン、登録、投稿、通報、リアクションにレート制限があり、モデレーション操作は監査ログに残る |

### Should（全校に開放する前に）

| 機能 | 理由 | 補足 |
| --- | --- | --- |
| ページネーションまたは「もっと見る」 | 500 スレッドあるボードは使えない | 実装済み。番号付きページで 1 ページ 20 件 |
| 全文検索の索引 | 数千件なら `contains` で足りる。順位付けと日本語の分かち書きには FTS5 か Postgres FTS が要る | 検索の遅さや精度が不満になってから入れる |
| パスワード再設定 | ロックアウトされた利用者を手作業で助けずに済む | 手作業の再設定コマンドは実装済み。利用者自身で行うメール再設定には送信事業者が要る |
| 禁止・ミュート | 繰り返す相手には単発の削除では足りない | 期限と理由を付ける |
| プライバシー通知と利用規約 | 学校の承認に必要 | `/rules`、`/privacy`、`/moderation-policy` として公開済み。文面は担当教員の承認がまだ必要 |

### Could（掲示板が軌道に乗ってから）

- メールダイジェストによる通知。アプリ内の未読表示は実装済み。
- 「+1」返信の代わりのリアクション。
- ボードごとのタグの決まった語彙。ヒントは実装済みで、強制は未着手。
- プロフィールの飾り付け（アイコン、自己紹介）。読み取り専用のプロフィールは実装済み。
- 下書きの自動保存。
- モデレーター限定の、削除済み内容を含む全文検索。

### Won't（今年度はやらない）

- リアルタイムチャットやダイレクトメッセージ。
- 画像、動画、ファイルのアップロード。
- 匿名投稿。
- 連合、または学外からの自由な登録。
- ネイティブのモバイルアプリ。
- AI によるコンテンツモデレーション。将来は補助に使えても、責任は人間が持ちます。

## ユーザーストーリーと受け入れテスト

### US-1 登録してログインする

生徒として、本名を明かさずに投稿できるよう、ユーザー名とパスワードだけのアカウントが欲しい。

- まっさらな状態から最初に登録したアカウントは `ADMIN` になる。
- 既存のユーザー名なら、登録は `username-taken` を返し、パスワード以外の入力内容を保持する。
- 正しい認証情報なら、ログインは HttpOnly のセッション Cookie を設定し、元いたページへリダイレクトする。
- 誤った認証情報なら、ユーザー名とパスワードのどちらが誤りでも同じ一般的なエラーを表示する（メッセージからアカウントの有無を推測されない）。

### US-2 アカウントなしで読む

入学希望者として、登録する前に掲示板を読みたい。

- ゲストはボード、スレッド一覧、投稿を閲覧できる。
- ゲストには返信フォームの代わりに「ログインして返信」が表示される。
- ゲストにモデレーションへのリンクは表示されない。

### US-3 スレッドを立てる

部活動の役員として、後からでも見つけてもらえる行事スレッドを立てたい。

- `/new?board=<slug>` から来た場合、ボードの選択欄はそのボードであらかじめ埋まっている。
- アーカイブ済みのボードはサーバー側で拒否される。
- 不正なタイトルや本文なら、ボードの選択を失わずにエラー付きでフォームへ戻る。
- 作成後、投稿者は新しいスレッドへリダイレクトされる。

### US-4 返信する

生徒として、質問に答えたい。

- 返信はスレッドの末尾に表示され、スレッドはボードの先頭へ移動する。
- ロックされたスレッドは `thread-locked` で返信を拒否する。
- 削除されたスレッドは返信を拒否する。

### US-5 通報する

生徒として、相手と直接向き合わずに投稿を知らせたい。

- ログイン済みの利用者は、表示中のすべての投稿で通報フォームを使える。
- 3〜500 文字の理由が必須。
- 通報者には確認メッセージが表示される。投稿は自動では隠れない。
- 通報は `/moderation` に古い順で表示される。

### US-6 モデレーションする

モデレーターとして、通報をすばやく片付けたい。

- 通報された投稿を削除すると論理削除され、通報は `removed` として解決される。
- 通報を却下すると `dismissed` として解決され、投稿はそのまま残る。
- スレッドをロックすると返信はできなくなるが、読むことはできる。
- スレッドを削除すると一覧から消え、モデレーターはボードへ戻る。
- すべての操作に `MODERATOR` または `ADMIN` のセッションが必要。ボタンを隠すことは制御ではない。

## v0.1 の完了条件

- [x] `pnpm build` が型エラー 0 で成功する。
- [x] `pnpm lint` が成功する。
- [x] 本番ビルドに対して一連の流れが動く: 登録 → スレッド → 返信 → 通報 → モデレーション → ロック → ログアウト。
- [ ] 学校または教員が承認したアカウントが所有する HTTPS の URL に配備されている。
- [ ] シード／デモアカウントが削除または変更されている。
- [ ] バックアップが毎日実行され、復旧が 1 回テストされている。
- [ ] モデレーターの研修が済み、通報の対応目標が公開されている。
- [ ] 担当教員と学校の管理職が承認している（`docs/ja/06` を参照）。

## 明示的な削減ライン

時間が足りない場合、次の順番で削り、そこで止めます。

1. 通知とリアクション（MVP には入れない）。
2. 検索。
3. メール確認と、利用者自身によるパスワード再設定（手作業の再設定は実装済み）。
4. スレッドの固定（シード済みの固定スレッドは残してよい）。
5. 通報キュー（教員が同意した場合 **に限り**、共有のモデレーション用メールボックスで代替。説明責任は弱くなり、あくまで一時的な措置）。

削ってはいけないもの: 権限チェック、論理削除、通報経路、バックアップ、教員へのエスカレーション経路。これらがあるかどうかが、掲示板と「負債」の分かれ目です。
