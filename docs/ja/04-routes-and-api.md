# ルートとフォームのエンドポイント

> 日本語版です。英語版が正本です: [English](../04-routes-and-api.md)

これらのエンドポイントは、このアプリケーションの HTML フォームを処理するために用意しています。**バージョン付きの公開 API ではありません。** 将来モバイルクライアントを作るなら、バージョンを明示した JSON API が別途必要です。

## 1. ページ

| パス | アクセス | 目的 |
| --- | --- | --- |
| `/` | 公開 | 唯一の横断フィード。`sort=latest\|hot\|rising`、`filter=all\|saved\|mine`、`q` でタイトル・本文・タグを検索。表示は最大 30 件 |
| `/b/[slug]` | 公開 | ボードのホーム。スレッド数・参加メンバー数・投稿数・最終更新を出すバナー、その下にスレッドを 1 ページ 20 件。固定が先、次に活動順・人気順・急上昇順 |
| `/boards` | 公開 | `/` へリダイレクト。ボード一覧は左側の欄とモバイルのドロワーにあります |
| `/boards/new` | ログイン済み | コミュニティボードの作成。1 アカウント 3 件まで、1 時間 5 件まで。slug はフォームの入力値 |
| `/t/[id]` | 公開 | 全投稿を番号付きの木構造で並べたスレッド、返信フォーム、リアクション |
| `/t/[id]/edit` | 作成者 | 投稿から 15 分以内に、タイトル・最初の投稿・タグを編集 |
| `/t/[id]/export` | 公開 | スレッドをプレーンテキストのファイルとしてダウンロード |
| `/u/[username]` | 公開 | プロフィール。身元バナー、4 つの数（スレッド・投稿・もらったいいね・参加日）、最近のスレッドと最近の返信を 2 つのタブで表示 |
| `/new` | ログイン済み | スレッド作成。ゲストは `/login?next=/new` へリダイレクト |
| `/login` | 公開 | ログインフォーム。ログイン済みの利用者はリダイレクト |
| `/register` | 公開 | 登録フォーム。最初のアカウントは `ADMIN` になる |
| `/threads` | 公開 | `/` へリダイレクト。`q`・`filter`・`sort` は引き継ぐ |
| `/search` | 公開 | `q` を付けて `/` へリダイレクト。`tag` は `#tag` の検索語になる |
| `/bookmarks` | ログイン済み | `/?filter=saved` へリダイレクト |
| ログイン後の各ページ | ログイン済み | ヘッダーに通知の受信箱（返信・コメント・いいね・保存）と未読数を出す。各項目は特定の投稿（`#p-<id>`）へリンクする。スレッド単位のいいね・保存は最初の投稿を指す |
| `/moderation` | モデレーター／管理者 | 未処理の通報（1 ページ 10 件、`page` 指定可）、自動フラグ、最近の監査ログ。管理者にはコミュニティボードのアーカイブ操作も出す。それ以外の利用者はリダイレクト |
| `/rules` | 公開 | コミュニティルール。表示言語に合わせて出し分ける |
| `/privacy` | 公開 | プライバシー通知。保存する情報、Cookie、保存期間、閲覧できる人 |
| `/moderation-policy` | 公開 | 通報、自動フラグ、異議申し立て、エスカレーションの扱い |
| `/health` | 公開 | JSON の稼働確認。`{"status":"ok","database":"ok"}` を返し、データベースに触れないときは 503 |
| 未知のパス | 公開 | カスタム 404 |

すべてのページはリクエストごとにサーバーで描画します。クライアント側でデータを取得することはありません。

### レート制限

すべてプロセス内の固定ウィンドウで、IP かアカウントをキーにします。1 つの教室が同じ学校の IP を共有することがあるため、既定値はかなり緩めにしています。

| 操作 | 既定の制限 |
| --- | --- |
| ログイン | IP + ユーザー名ごとに 10 分 10 回 |
| 登録 | IP ごとに 1 時間 60 回 |
| スレッド作成 | アカウントごとに 1 時間 10 回 |
| 返信 | アカウントごとに 1 時間 60 回 |
| 通報 | アカウントごとに 1 日 30 回 |
| いいね／保存 | アカウントごとに 1 時間 300 回 |
| ボード作成 | アカウントごとに 1 時間 5 回、所持は 3 件まで |

ログインに成功すると、その IP + ユーザー名のカウンターを消します。パスワードを一度打ち間違えてから正しく入れても、ロックアウトには近づきません。制限に当たると `error=rate-limited` を付けて元のページへ戻します。レスポンスはリダイレクトなので `Retry-After` は返しません。再起動するとカウンターは消えます。

制限はコードを直さずに環境変数で変えられます。`RATE_LIMIT_<NAME>_LIMIT` と `RATE_LIMIT_<NAME>_WINDOW_MIN` の組で、`<NAME>` は `LOGIN`、`REGISTER`、`THREAD`、`REPLY`、`REPORT`、`LIKE`、`BOOKMARK` のいずれかです。たとえば以前のログイン制限に戻すなら、`RATE_LIMIT_LOGIN_LIMIT=5` と `RATE_LIMIT_LOGIN_WINDOW_MIN=10` を設定します。詳しくは `docs/ja/07-operations.md` の第 2 節を見てください。

### 検索と並べ替え

一覧はフィード（`/`）だけです。受け取るのは `q`（100 文字まで）、`filter=all|saved|mine`、`sort=latest|hot|rising` です。`q` はスレッドのタイトル、表示中の投稿の本文、タグを `contains` で照合します。`#` で始まる語はタグを優先して照合します。`saved` と `mine` はログインが必要で、ゲストには空の一覧ではなくログインの案内を出します。

検索語がないときのフィードは読むための面です。`latest` は直近 30 件、`hot` と `rising` は直近 100 件を順位付けして 30 件に切ります。

検索語があるときは、フィードが検索機になります。

- 候補は表示中の一致すべて（順位付けのため最大 500 行を取得）。直近 30 件の制限はかからないので、前学期のスレッドも見つかります。
- 順位付けはアプリケーション側（`src/lib/search.ts`）で、公開した重みを使います。タイトル一致が各 5（最大 3 か所）、タイトル完全一致に 12、タグ一致が各 3、本文一致が各 1（最大 5 か所）、さらに反応数の小さな加点。同点は `lastPostAt` の新しい順です。
- `sort=latest` はその関連度順を保ち、`hot` と `rising` は同じ候補を並べ替えます。
- 結果は 1 ページ 20 件（`page` は 1 始まり、最後のページに丸める）で、見出しに一致件数を出します。ページ 1 は `?page=1` を付けない URL を正とします。
- 検索語は結果のタイトルとタグに `<mark class="hl">` で付き、各結果のリンクは `?q=` を引き継いでスレッドへ移動します。スレッドでは最初の投稿と返信の本文でも同じ語を強調します。`#p-<id>` 付きのリンクでは、その投稿を約 2 秒間点滅させて、どこへ着地したか分かるようにします。

この選択は SQLite の FTS ではなく `LIKE` とアプリ側の順位付けです。2 文字の日本語語が壊れず（trigram では壊れます）、この規模では予算内に収まります。候補の上限と重みの表が、最初に見直す 2 つのつまみです（ADR-0022）。

- `latest` は `lastPostAt` の降順で、最大 30 件です。
- `hot` は「いいね × 3 + 保存 × 2 + 返信数 + 直近 72 時間の活動への加点（最大 3）」で、直近 100 件から上位 30 件を残します。
- `rising` は「（いいね × 2 + 返信数 × 3 + 1）÷（最終投稿からの時間 + 6）」です。新しいスレッドが古い人気スレッドより上に来るようにし、72 時間動きのないスレッドは一覧から外れます。

ボードページも同じ `sort` と、1 始まりの `page` を受け取ります。1 ページは 20 件です。`page` が最後のページを超えたときは最後のページに丸め、ページ 1 は `?page=1` を付けない URL を正とします。`sort=hot` と `sort=rising` では上位 100 件をアプリケーション側で並べ替えてからページに分けます。

`/threads`、`/search`、`/bookmarks` はクエリを引き継いでフィードへリダイレクトします。フィードに統合する前に共有されたリンクでも、同じ絞り込みに着地します。

方針ページは `src/lib/policies.ts` にある静的な二言語の本文を表示します。文面をコードとして持つので、英語と日本語は同じコミットで変わります。公開前に、担当教員がこの文面を承認する必要があります。

## 2. 変更系エンドポイント

すべてのエンドポイントは `application/x-www-form-urlencoded` または `multipart/form-data`（標準の HTML フォーム形式）を受け取ります。クロスオリジンの `Origin` ヘッダーは拒否し、成功時は `303 See Other` を返してブラウザに `GET` を行わせます。

### `POST /api/auth/register`

| フィールド | 必須 | ルール |
| --- | --- | --- |
| `username` | はい | 3〜20 文字、`[A-Za-z0-9_]`、小文字化 |
| `email` | いいえ | 有効なアドレス、254 文字以内、一意 |
| `password` | はい | 10〜200 文字、前後の空白は削除しない |
| `next` | いいえ | 同一サイトのパスのみ |

- 成功: セッション Cookie を設定し、`next` または `/` へリダイレクトします。
- 失敗: `/register?error=<code>` へリダイレクトします。パスワードを画面に戻すことはありません。
- コード: `invalid-input`、`username-taken`、`email-taken`。

### `POST /api/auth/login`

| フィールド | 必須 |
| --- | --- |
| `username` | はい |
| `password` | はい |
| `next` | いいえ |

- 成功: セッション Cookie を設定し、`next` または `/` へリダイレクトします。
- 失敗: `/login?error=invalid-credentials`。利用者が存在しない場合もパスワードが違う場合も、同じメッセージを返します。
- IP + ユーザー名ごとに 10 分 10 回を超えると `error=rate-limited` を返します。ログインに成功するとカウンターは消えます。

### `POST /api/auth/logout`

- 有効な Cookie があればセッション行を削除し、Cookie を消して `/?notice=signed-out` へリダイレクトします。

### `POST /api/locale`

| フィールド | 必須 | 値 |
| --- | --- | --- |
| `locale` | はい | `en` または `ja` |

- 画面は、利用者が切り替えるまで日本語です。1 年間有効な `locale` Cookie を設定し、同じホスト上の直前のページへ戻します。使える `Referer` がないときは `/` へ戻します。
- 未知の値は無視します。その場合も、現在のページはそのまま再読み込みします。

### `POST /api/threads`

| フィールド | 必須 | ルール |
| --- | --- | --- |
| `boardId` | はい | 存在し、アーカイブされていないボード |
| `title` | はい | 3〜120 文字 |
| `body` | はい | 1〜10,000 文字 |
| `tags` | いいえ | スペースかカンマ区切り、先頭の `#` は任意、最大 5 個 |

- 認証: ログイン済みの利用者。
- 成功: `Thread` と最初の `Post` を原子的に作成し、`/t/<id>` へリダイレクトします。
- 失敗: `/new?board=<slug>&error=<code>`。
- コード: `board-not-found`、`invalid-input`、`login-required`。

### `POST /api/boards`

| フィールド | 必須 | ルール |
| --- | --- | --- |
| `name` | はい | 2〜30 文字。入力どおりに表示します |
| `slug` | はい | 3〜30 文字、`^[a-z0-9](?:[a-z0-9-]{1,28}[a-z0-9])$`、小文字に変換、予約語は不可、一意 |
| `description` | はい | 2〜200 文字 |
| `tags` | いいえ | スペースかカンマ区切り、最大 8 個。新しいスレッドへの提案タグ |

- 認証: ログイン済みの利用者。ゲストは `/login?next=/boards/new` へリダイレクトします。
- 成功: 作成者を所有者とする `COMMUNITY` ボードを作り、`/b/<slug>` へリダイレクトします。
- 制限: 1 アカウントが持てるボードは 3 件、作成は 1 時間 5 件まで。
- 失敗: `/boards/new?error=<code>`。コードは `invalid-slug`、`slug-taken`、`invalid-input`、`rate-limited`、`board-limit`。

### `POST /api/profile`

| フィールド | 必須 | ルール |
| --- | --- | --- |
| `bio` | いいえ | 200 文字まで。空にすると消えます |
| `avatarColor` | いいえ | `#rrggbb`。それ以外の値は既定の配色に戻します |
| `avatarRing` | いいえ | `#rrggbb`。扱いは同じ |

- 認証: ログイン済みの利用者。自分自身のプロフィールだけを保存します。
- 成功: `/u/<username>?notice=profile-saved` へリダイレクトします。
- アバターの文字色は背景の明るさから計算するため、色のフィールドは保存しません。

### `POST /api/notifications/seen`

- 認証: ログイン済みの利用者。本文は不要です。
- `User.notificationsSeenAt` を現在時刻にします。未読のバッジが消えます。出来事そのものは組み立てているだけなので、作成も削除もしません。
- 項目を開くと必ず移動します。別のページへのリンクはそのまま遷移し、いま開いているページへのリンクはハッシュを設定して投稿までスクロールし、点滅させます（Next のルーターは同じパスへの push を何もしないため、パネル側で処理します）。
- `Accept: application/json` のときは `{ok:true}`（ゲストは 401）。それ以外は `/` へリダイレクトします。

### `GET /api/pulse`

- 認証: 不要。1 つの数値 `{at}` を返します。
- `at` は、読者がいま見ている可能性のあるものが最後に変わった時刻です。`Post.updatedAt`、`Thread.updatedAt`、最新のスレッドいいね・投稿いいね・保存・通報のうち最も新しいものを取ります。
- 編集と論理削除でもこの数値が動く必要があるため、作成時刻ではなく `updatedAt` を見ます。「最新の行」だけを見ていると、モデレーターが投稿を削除したときに何も作られないので、スレッドページが古いままになります。
- `AutoRefresh` はタブが表示されていて入力欄にフォーカスがない間、12 秒ごとにこれを問い合わせ、トランジションの中でルートを更新し、直前まで画面になかった id の要素を点滅させます。

### `POST /api/boards/[id]/archive`

| フィールド | 必須 | 値 |
| --- | --- | --- |
| `action` | はい | `archive` または `restore` |

- 認証: `ADMIN` のみ。モデレーターは `/moderation?error=forbidden` へ戻されます。部活のボードを閉じるのは日々のモデレーションではなく、サイト全体の判断だからです。
- 成功: `Board.isArchived` を切り替え、監査ログ（`board.archive` / `board.restore`）を 1 行書き、`/moderation?notice=board-archived`（復元なら `board-restored`）へリダイレクトします。
- 毎日の `pnpm archive-boards` が、`BOARD_ARCHIVE_DAYS` 日のあいだ動きのないコミュニティボードに対して同じ変更を自動で行います。

### `POST /api/threads/[id]/posts`

| フィールド | 必須 | ルール |
| --- | --- | --- |
| `body` | はい | 1〜10,000 文字 |
| `tags` | いいえ | スペースかカンマ区切り、先頭の `#` は任意、最大 5 個 |

- 認証: ログイン済みの利用者。
- 前提: スレッドが存在し、削除されておらず、ロックされていないこと。
- 成功: `Post` を挿入し、同じトランザクションで `Thread.lastPostAt` を更新して、`/t/<id>#p-<postId>` へリダイレクトします。
- `Accept: application/json` を付けたときは、リダイレクトの代わりに `{comment}` を返します。中身はコメント木がそのまま描ける形の新しい投稿で、時刻は表示言語に合わせます。ゲストには `401` を返します。返信フォームはこれを使って、ページ全体を読み直さずに投稿を挿し込みます。
- 失敗コード: `thread-locked`、`invalid-input`、`thread-not-found`。

### `POST /api/threads/[id]/edit`

| フィールド | 必須 | ルール |
| --- | --- | --- |
| `title` | はい | 3〜120 文字 |
| `body` | はい | 1〜10,000 文字。最初の投稿を置き換える |
| `tags` | いいえ | スレッド作成と同じルール。現在のタグ一式を置き換える |

- 認証: スレッドの作成者本人のみ。`Thread.createdAt` から 15 分以内に限ります。
- 前提: スレッドが存在し、削除されておらず、ロックされていないこと。
- 成功: タイトルと最初の投稿を更新し、`Thread.editedAt` を設定し、タグを置き換えて `/t/<id>?notice=thread-edited` へリダイレクトします。
- 編集後の本文が要注意語に一致した場合、その投稿に未処理の `AUTO` 通報がなければ 1 件だけ作ります。
- 失敗コード: `edit-not-allowed`、`invalid-input`、`not-found`。

### `POST /api/threads/[id]/lock`

- 認証: `MODERATOR` または `ADMIN`。本文は不要です。
- `isLocked` を反転し、スレッドへ戻します。
- 失敗コード: `forbidden`、`thread-not-found`。

### `POST /api/threads/[id]/delete`

- 認証: スレッドの投稿者本人、または `MODERATOR` / `ADMIN`。本文は不要です。
- `isDeleted = true` にして、ボードへリダイレクトします。
- 失敗コード: `forbidden`、`thread-not-found`。

### `POST /api/posts/[id]/delete`

- 認証: 投稿者本人、または `MODERATOR` / `ADMIN`。本文は不要です。
- `isDeleted = true` にして `/t/<threadId>#p-<postId>` へリダイレクトします。アンカーまで戻すのが要点で、スレッド先頭に飛ばされるのではなく、その投稿が置き換わったプレースホルダーの位置に着地します。クリックの結果が必ず目に見える形になります。
- 投稿は言語に合わせたプレースホルダーとして残りますが、本文は描画結果からもブラウザへ送る RSC ペイロードからも取り除かれます。CSS で隠しているだけではありません。返信はプレースホルダーの下にぶら下がったまま読めます。
- 失敗コード: `forbidden`、`not-found`。

### `POST /api/posts/[id]/like`

- 認証: ログイン済みの利用者。本文は不要です。
- 利用者 1 人につき投稿 1 件のいいねを切り替え、`Post.likeCount` だけを更新します。`Thread.likeCount` は最初の投稿へのいいね数なので、返信へのいいねではスレッドの合計は変わりません。
- `/t/<threadId>#p-<postId>` へ戻します。
- リクエストが `Accept: application/json` を送ってきた場合は、リダイレクトの代わりに `{active, count}` を返します（レート制限時は 429）。JavaScript のない環境では、これまでどおりフォームが動きます。

### `POST /api/threads/[id]/bookmark`

- 認証: ログイン済みの利用者。本文は不要です。
- 利用者 1 人につきスレッド 1 件の保存を切り替え、`Thread.bookmarkCount` を更新します。
- 同じホスト上の直前のページ、またはスレッドページへ戻します。
- `Accept: application/json` のときは、代わりに `{active, count}` を返します（レート制限時は 429）。

### `POST /api/reports`

| フィールド | 必須 | ルール |
| --- | --- | --- |
| `postId` | はい | 存在する投稿 |
| `reason` | はい | 3〜500 文字 |

- 認証: ログイン済みの利用者。
- 成功: `Report` を作成し、`?notice=reported` を付けてスレッドへリダイレクトします。
- 同じ利用者と同じ投稿の未処理の通報は 1 件だけです。2 回目は `?notice=already-reported` で戻り、行は増えません。競合時の受け皿は部分一意インデックス `Report_one_open_per_reporter_post` です。
- 失敗コード: `report-invalid`。

### `POST /api/reports/[id]/resolve`

| フィールド | 必須 | 値 |
| --- | --- | --- |
| `action` | はい | `remove` または `dismiss` |

- 認証: `MODERATOR` または `ADMIN`。
- `remove`: 通報された投稿を論理削除し、通報を `removed` にします。
- `dismiss`: 投稿はそのままにし、通報を `dismissed` にします。
- どちらの場合も `/moderation` へリダイレクトします。

### 未読の表示

`/`、`/b/[slug]`、`/t/[id]` は、ログイン中の利用者の `ThreadRead` を読みます。その行がなければ、または `Thread.lastPostAt` が `lastReadAt` より新しければ、スレッドに「新着」を表示します。スレッドページを描画するときに、現在時刻でその行を upsert します。ゲストは既読状態を持たないため、バッジは表示しません。書き込みは冪等で、保存するのは時刻だけです。

## 3. エラー処理

JSON のエラー形式はありません。利用者に見せる失敗は、クエリ文字列に短いコードを付けて該当ページへ戻します。コードを英語の文に対応付けるのは `src/lib/messages.ts` です。未知のコードは汎用の「フォームを確認してください」に落ちるため、手で作った URL からページに任意のテキストを差し込むことはできません。

想定外の失敗（データベースの停止、未処理の例外）は Next.js が 500 として返します。公開前にエラー監視を追加してください。`docs/ja/07-operations.md` を参照してください。

## 4. Cookie

| 属性 | 値 | 理由 |
| --- | --- | --- |
| 名前 | `toyooka_session` | |
| 値 | 16 進 64 文字（32 バイトのランダム） | 256 ビットのエントロピー |
| `HttpOnly` | true | JavaScript から読めない |
| `SameSite` | `Lax` | ほとんどのクロスサイトフォーム送信を防ぐ |
| `Secure` | 本番では true | HTTPS が必要 |
| `Path` | `/` | |
| `Expires` | 30 日 | |

2 つ目の Cookie `locale` は、画面の表示言語（`en` または `ja`）を 1 年間保存します。この Cookie がないときは日本語です。こちらも `HttpOnly` と `SameSite=Lax` を設定します。身元を示す情報は含まないので、消しても問題ありません。

`COOKIE_SECURE=false` は、学校の LAN で平文 HTTP を使う場合のためだけに用意しています。公開インターネットでは使わないでください。

## 5. CSRF とオリジンの確認

`SameSite=Lax` があるため、クロスサイトの POST で Cookie が設定されることはすでに防げています。そのうえで多層防御として、すべての POST ハンドラーが `isSameOrigin()` を呼び、`Origin` ヘッダーが別ホストを指していれば拒否します。`Origin` ヘッダーのないリクエスト（curl や一部のプライバシーツール）は許可します。攻撃者が、クロスサイトのフォーム送信でブラウザに `Origin` を省かせることはできないからです。

## 6. キャッシュ

どのエンドポイントもキャッシュしません。ページは動的です。レスポンスのヘッダーにはログイン中の利用者名が入るため、アプリの前段に置いた CDN にレスポンスをキャッシュさせてはいけません。
